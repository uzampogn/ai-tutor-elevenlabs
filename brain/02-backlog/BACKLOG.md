## How beads fits in

[beads](https://github.com/steveyegge/beads) (`bd`) is a required component of
this harness — status and dependencies that survive compaction and session death.

- **1 bead per item**, created by `/design-session`, carrying the item title,
  the **1-line user outcome** (what this buys the user — distilled from the
  observation's C line), the `Owns` file boundary, its dependencies (`bd dep`),
  and the paths to its `spec.md` + `plan.md`.
- **`bd ready` is the queue.** The orchestrator claims with
  `bd update <id> --status=in_progress` and closes with `bd close <id>`,
  regenerating this file in the same step.
- **Single writer:** the orchestrator and design sessions. Workers never run
  `bd` — they report via plan checkboxes and `../03-build-reports/`, so parallel
  worktrees never collide on the tracker.
- **Session close:** `bd export -o .beads/issues.jsonl`. The Stop hook
  (`../../.claude/hooks/stop-bead-check.sh`) blocks a session from ending with
  in-progress beads unhandled.
- **Richer view (optional):** `bv`, the beads TUI — board and dependency graph.
